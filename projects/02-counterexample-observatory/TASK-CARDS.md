# Concrete counterexample-search task cards

These are real mathematical research targets, not invented toy puzzles. They are deliberately framed so that an agent can produce useful work without pretending that it solved an open problem.

## Card C-01: the 1/3–2/3 poset frontier

### The real conjecture

Every finite poset that is not a total order has an incomparable pair `(x, y)` such that, among all its linear extensions, `x < y` occurs with probability between `1/3` and `2/3`.

This is the **1/3–2/3 Conjecture**, an open problem in order theory. Exhaustive searches are known for small posets; published discussions report no counterexample among posets with up to nine elements in relevant searches.

### Overnight mission

1. Reproduce the result for non-isomorphic posets through a smaller size first (for example 6 or 7 elements).
2. Compute every linear extension exactly, using integer counts — never floating point.
3. Search the next feasible restricted frontier: connected posets, width-3 posets, or all non-isomorphic posets at the next size that the run can complete.
4. If any poset has no balanced pair, save its Hasse diagram, relation matrix, all exact pair probabilities, and a standalone verifier.

### Why this is good

A true counterexample would be major. The normal outcome is still publishable-quality computational evidence: an independently reproducible extension of a finite frontier or a refined catalogue of extremal posets.

### Verification

The verifier must enumerate linear extensions separately from the search program and check every incomparable pair exactly.

Sources: [open-conjecture Lean formalisation](https://samuelschlesinger.github.io/open-conjecture-formalizations/order-theory/one-third-two-thirds/), [background and small-case search](https://users.math.msu.edu/users/bsagan/Papers/Old/otc.pdf).

## Card C-02: Union-closed families stress test

### The real conjecture

For every nontrivial finite family of sets closed under union, some ground-set element belongs to at least half the sets. This is **Frankl's Union-Closed Sets Conjecture**, open since 1979.

### Overnight mission

1. Represent a family on `[m]` as bitmasks and validate union-closure directly.
2. First reproduce a known small-case result from the literature.
3. Search a clearly stated frontier or a structured subclass: separating families, families generated by a fixed number of sets, fixed minimum set size, or fixed number of member sets.
4. Optimise for a family whose *maximum* element frequency is as small as possible.
5. Save a candidate family only if a second, tiny verifier confirms closure and each frequency.

### What constitutes a result

- A family where every element has frequency strictly below `|F| / 2` is a counterexample to the full conjecture.
- Otherwise, a new exact lower bound for a stated finite class, a minimal extremal family, or a verified computational reproduction is useful.

### Important warning

The full conjecture is extremely hard. Do not report a claimed counterexample until a separate implementation has checked it and the agent has compared every convention with the source statement. Incorrect "counterexamples" often arise from accidentally allowing duplicate sets, an empty-only family, or a non-closed family.

Sources: [definition and early small cases](https://www.sciencedirect.com/science/article/pii/0097316592900686), [recent context](https://arxiv.org/abs/2310.02482).

## Card C-03: Auditing fresh finite claims rather than famous conjectures

### The real task

Select a recently posted public claim with a finite or finitely parameterised core — preferably a Lean package, a graph-theory preprint, or an agent-generated research post. Extract one exact statement that should hold for all objects below a modest size, then search for a counterexample.

Good feeds:

- [MoltArxiv](https://github.com/MoltArxiv/MoltArxiv);
- [ProofAtlas](https://www.proofatlas.ai/);
- [TheoremDB](https://theoremdb.org/);
- fresh arXiv combinatorics papers whose source code is public.

### Overnight mission

1. Choose one claim with a stable URL, explicit definitions, and a genuinely finite small-case implication.
2. Translate it into an executable predicate and hand-check two examples.
3. Enumerate the full small domain or formulate it as SAT/SMT with an independent certificate checker.
4. If a witness is found, minimise it and write a neutral local audit report; if none is found, report the exact covered domain.

### Why this is the highest-probability discovery route

It does not rely on beating decades of expert work on a famous conjecture. It targets the growing volume of new, sometimes weakly reviewed mathematical claims and produces a concrete, checkable correction or replication artifact.

### Verification

Keep the source snapshot/hash, the formalised statement, raw witness, and independent verifier together. Do not publish or accuse anyone automatically.

## Optional hard-mode seed: Seymour's Second Neighborhood Conjecture

For every finite oriented graph, there is a vertex whose number of exact second out-neighbours is at least its out-degree. The conjecture is open, but recent work has already proved exhaustive small cases and raised structural lower bounds on any counterexample.

Do **not** ask a Flash agent to solve it wholesale. A valid scoped mission is: reproduce the published small-case enumeration, then test one explicitly defined new subclass or a proposed stronger variant. Any claimed counterexample needs a standalone graph checker.

Sources: [recent small-case computation](https://arxiv.org/abs/2601.21563), [recent structural bound](https://arxiv.org/abs/2608.11530).
